# Bounded Delegation Brief

## Objective

State the exact outcome this child owns.

## Context

Provide only the relevant decisions, source files, and constraints.

## In scope

- Files or symbols the child may inspect or change.
- The specific slice this child owns.

## Out of scope

- Files and decisions owned by the orchestrator or another child.
- External actions the child must not take.

## Acceptance checks

List observable outcomes that can fail.

## Verification

Give the focused command authorized by the user and permitted by the repository. If no check may run, state that.

## Return format

- Result summary and changed files.
- Diff or artifact location.
- Checks run and results.
- Corrections, assumptions, or unresolved issues.
- Provider/model used for evaluation runs.
