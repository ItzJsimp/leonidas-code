# Verification before closing a task

Use the task's acceptance criteria and the project's smallest relevant check. For a bug, reproduce the failing behavior before fixing it when feasible, then run the same check afterward. Record actual commands, exit codes, or observable results on the task card.

An implementation claim is not proof. If a check cannot run, record the limitation and keep the task in the appropriate review or blocked state. Use the store's existing completion helper if available; otherwise update the canonical card with a resolution and evidence. Stage only files belonging to the authorized task when committing.
